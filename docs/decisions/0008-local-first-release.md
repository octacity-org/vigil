# 0008. The first release runs locally, with Docker

- **Status:** accepted
- **Date:** 2026-10-31
- **Decided by:** @BerkeDurdu
- **Discussion:** to be linked

## Context

`docs/VIGIL.md` planned a public web site: an API server, a hosted database and a static frontend. Two things argue against starting there:

- **Hosting.** Free hosting tiers either sleep (Render's free web services stop after 15 minutes idle and take about a minute to wake), forbid commercial use (Vercel Hobby, GitHub Pages) or are too small for the data. The free PostgreSQL tiers checked (Neon, Supabase) give about 0.5 GB per project, while one quarter is about 370,000 values.
- **Publishing KAP data.** A public site republishes numbers derived from KAP filings. Decision 0001 avoids redistributing KAP files; a local tool keeps that position, because each user downloads the data from KAP.

## Options considered

1. **Public web site** as in `VIGIL.md`. Needs hosting and maintenance from day one.
2. **Static site** generated by CI. Cannot follow new disclosures between builds and cannot serve user-specific features later.
3. **Local application.** Every user runs Vigil on their own computer with Docker; nothing is published.

## Decision

Option 3 for the first release.

- Vigil ships as Docker images and a `docker-compose.yml`. One command starts it; the user opens `http://localhost`.
- Ports are bound to `127.0.0.1`, so nothing is reachable from the network.
- There are no user accounts, no login and no paid tiers in this release.
- Each installation downloads its own data from KAP. The polite-access rules (one request at a time, waits between requests, single-company downloads only for new disclosures; #38, #40) are built in and cannot be changed by the user.
- A hosted service can be added later on top of the same code; the API keeps room for it (see `docs/ARCHITECTURE.md`).

## Consequences

- No hosting cost and no server to maintain.
- Users need Docker Desktop. A launcher script and a step-by-step install guide are part of the release.
- KAP sees one client per installation; the built-in limits keep each one polite.
- Disk use grows with the quarters a user downloads (raw files are about 1 GB per quarter unpacked); the app shows it.
- Supersedes the hosting and public-site parts of `VIGIL.md` §11 for this release.
